## The central question

You have a pile of raw scraped text. How do you turn it into a number you can
actually defend in a report? That's the whole session — one real, small pipeline,
end to end: acquire text → structure it → check its quality → define one KPI from
it → decide what's safe to publish → visualize it for a decision. Every stage maps
to something from the CM lectures; each section below says which.

### The one real scraping mechanic this course hasn't covered yet

TD1/TD2 are both pure API pipelines; TP1's optional jobspy step uses a library that
does the scraping for you. This is the first (and only) place you touch raw HTML and
a real `robots.txt` file directly.

`scripts/scrape_demo.py` (optional to run yourself — a good instructor demo either
way):

```python
import requests
from bs4 import BeautifulSoup

URL = "https://fr.wikipedia.org/wiki/Le_Mans"
USER_AGENT = "ENSIM-BI-course-TD (educational, contact your-email@univ-lemans.fr)"

def robots_allows(url, user_agent="*"):
    # Minimal, real check -- confirmed by hand against fr.wikipedia.org/robots.txt
    # before writing this: /wiki/<Article> is allowed for User-agent: *, only
    # /wiki/Special:... and a few other prefixes are disallowed.
    #
    # rp.read() uses urllib under the hood, which respects HTTP_PROXY/HTTPS_PROXY --
    # on a network with an institutional proxy (this one included), that silently
    # intercepts the request and robotparser then defaults to "disallow everything"
    # with no visible error. Confirmed by real testing: rp.read() returned False for
    # a URL manually verified as allowed. Fetching the text with requests (already
    # proxy-bypassed everywhere else in this course) and handing it to rp.parse()
    # instead avoids the same silent-failure trap.
    import urllib.robotparser
    resp = requests.get("https://fr.wikipedia.org/robots.txt",
                         proxies={"http": None, "https": None},
                         headers={"User-Agent": USER_AGENT}, timeout=15)
    resp.raise_for_status()
    rp = urllib.robotparser.RobotFileParser()
    rp.parse(resp.text.splitlines())
    return rp.can_fetch(user_agent, url)

def main():
    allowed = robots_allows(URL)
    print(f"robots.txt allows fetching {URL}: {allowed}")
    if not allowed:
        raise SystemExit("robots.txt disallows this -- stopping, not scraping anyway.")

    resp = requests.get(URL, proxies={"http": None, "https": None},
                         headers={"User-Agent": USER_AGENT}, timeout=15)
    resp.raise_for_status()
    soup = BeautifulSoup(resp.text, "html.parser")

    title = soup.find("h1").get_text(strip=True)

    first_para = None
    for p in soup.find_all("p"):
        # A first, naive version of this loop (just "length > 40") grabbed a
        # disambiguation notice ("Pour les articles homonymes...") instead of real
        # article text -- confirmed on a live fetch. Wikipedia marks these notices
        # with a "hatnote" class on an ancestor, a well-known real convention;
        # skipping any <p> nested inside one is the actual fix, not a longer length
        # threshold (a short real sentence exists too, and a long hatnote could too).
        if p.find_parent(class_="hatnote"):
            continue
        text = p.get_text(strip=True)
        if len(text) > 40:
            first_para = text
            break

    print(f"\nPage title: {title}")
    print(f"First real paragraph ({len(first_para)} chars): {first_para[:200]}...")

    # One measurable variable extracted from unstructured HTML: population from the
    # infobox, found by label text rather than a fragile fixed CSS position.
    population = None
    for row in soup.select("table.infobox_v2 tr, table.infobox tr"):
        header = row.find("th")
        if header and "population" in header.get_text(strip=True).lower():
            cell = row.find("td")
            if cell:
                population = cell.get_text(" ", strip=True)
                break
    print(f"Extracted population field (unstructured -> one variable): {population!r}")

if __name__ == "__main__":
    main()
```

Install `beautifulsoup4` first: `pip install beautifulsoup4`. Run it, and you should
see: `robots.txt allows fetching .../wiki/Le_Mans: True`, the real page title, a real
first paragraph, and a real population figure extracted from the infobox — one HTML
page in, one measurable variable out, with a `robots.txt` check that actually works.

**Reflect:** `rp.read()` (the "obvious" one-liner version of this check) silently
returns "disallow everything" on a network with a proxy in front of it — with no
error, no warning, nothing that looks broken. `rp.parse()` (used above) doesn't have
this problem. In your own words: why is a pipeline stage that fails *silently* worse
than one that crashes loudly, for something whose whole job is "respect the rules

## Stage 2 — Structuring (CM5: agentic AI earns its place, or it doesn't)

`scripts/extract_skills.py` calls a local LLM (Ollama) to turn each posting's free
text into a list of concrete skills — the one stage in this whole pipeline where an
LLM is actually the right tool.

**Reflect, before you run anything:** CM5 argues agentic AI belongs at specific
pipeline stages, not everywhere. This TD extracts skills with an LLM, but nothing in
this course ever uses an LLM to decide, say, which application you actually sent or
what your real skill level is. Using CM5's own distinction (not just "because it's
convenient"), explain in your own words *why* free-text-to-structured-list is a good
fit for an LLM and a plain record of your own actions is not.

```python
import csv, json, sys, time
import requests

OLLAMA_URL = "http://127.0.0.1:11434/api/generate"
MODEL = "qwen3:8b"
N_POSTINGS = int(sys.argv[1]) if len(sys.argv) > 1 else 15
MAX_CHARS = 1500  # keeps each call fast enough for a live session -- see below

PROMPT_TEMPLATE = """Extract ONLY the concrete named tools/technologies/hard skills mentioned
in this job posting text (it may be in French or English). Do not include generic soft
skills, the job title, or company name.
Return ONLY valid JSON with one key:
- required_skills: array of strings (e.g. ["Python", "Docker", "AWS"]) -- empty array if none found.

TEXT:
{text}
"""

def call_ollama(prompt, retries=3, backoff=5):
    last_error = None
    for attempt in range(1, retries + 1):
        try:
            resp = requests.post(
                OLLAMA_URL,
                proxies={"http": None, "https": None},
                # think: False is the important flag here -- confirmed by real
                # testing that qwen3 defaults to an internal "thinking" pass before
                # answering, which alone turned a ~2s call into a 16s one on a
                # trivial prompt, and caused real, longer extraction prompts to
                # exceed a 120s timeout three times in a row (a genuine failure
                # observed while building this script, not a hypothetical one).
                json={"model": MODEL, "prompt": prompt, "format": "json", "stream": False, "think": False},
                timeout=(10, 120),
            )
            resp.raise_for_status()
            return json.loads(resp.json()["response"])
        except Exception as e:
            last_error = e
            print(f"    Ollama call attempt {attempt}/{retries} failed: {e}")
            if attempt < retries:
                time.sleep(backoff)
    raise RuntimeError(f"Ollama unreachable after {retries} attempts") from last_error

def main():
    with open("data/jobs_sample.csv", newline="", encoding="utf-8") as f:
        rows = [r for r in csv.DictReader(f) if r.get("description", "").strip()]
    rows = rows[:N_POSTINGS]
    print(f"Extracting skills from {len(rows)} postings (this takes real time -- "
          f"expect roughly 10-40 seconds per posting on a CPU-only laptop)...")

    postings = []
    start = time.time()
    for i, row in enumerate(rows, 1):
        text = row["description"][:MAX_CHARS]
        t0 = time.time()
        extracted = call_ollama(PROMPT_TEMPLATE.format(text=text))
        elapsed = time.time() - t0
        skills = extracted.get("required_skills", [])
        print(f"  [{i}/{len(rows)}] {row['title'][:50]!r} ({elapsed:.1f}s): {skills}")
        postings.append({
            "title": row["title"], "company": row.get("company"),
            "required_skills": skills,
        })

    with open("data/extracted.json", "w") as f:
        json.dump({
            "generated_at": time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime()),
            "postings": postings,
        }, f, indent=2, ensure_ascii=False)
    total = time.time() - start
    print(f"\nWrote data/extracted.json ({len(postings)} postings, {total:.0f}s total, "
          f"{total/len(postings):.1f}s/posting average)")

if __name__ == "__main__":
    main()
```

**Why `"think": false` is in there:** by default, this model runs an internal
"thinking" pass before answering every single call. On this exact prompt, that
turned a ~2-second call into a 16-second one — and on a real, longer extraction
prompt, it caused calls to time out entirely. Without this flag, this whole session
would be a lot slower or wouldn't finish. It's a small line with a real, measured
effect on whether a local-LLM pipeline like this is even practical.

Run it:

```

```

You should see one printed line per posting — a real list of specific tools and
technologies, taking roughly 10-40 seconds each. (For example, a posting for a
bench/tools engineering role might extract something like `['HIL', 'Python',
'MATLAB', 'CAPL', 'CAN', 'CI/CD']` — a genuine, specific list, not generic
buzzwords. Your own postings will extract differently; this is illustrative, not a

## Stage 4 — KPI definition (CM2: a KPI is a construct, not a neutral fact)

`scripts/compute_kpi.py` turns your extracted skills into one number.

**Reflect, before you read the code below:** the script is about to define
`TARGET_SKILL = "python"` — a choice someone (this manual) already made for you. If
you were building this dashboard for ENSIM's own curriculum committee, what single
skill would *you* choose to track first, and why? Write your answer down now, before
you see what number the default choice actually produces.

```python
import json, time
from collections import Counter

# One deliberately simple, deliberately editable KPI definition -- change
# TARGET_SKILL, or write a different KPI function entirely. Per this course's
# standing principle: a KPI is a construct you chose, not a neutral fact.
TARGET_SKILL = "python"

def load_extracted(path="data/extracted.json"):
    with open(path) as f:
        return json.load(f)["postings"]

def compute_kpi(postings, target_skill=TARGET_SKILL):
    n = len(postings)
    matching = [
        p for p in postings
        if any(target_skill.lower() in s.lower() for s in p.get("required_skills", []))
    ]
    all_skills = Counter()
    for p in postings:
        for s in p.get("required_skills", []):
            all_skills[s] += 1

    return {
        "generated_at": time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime()),
        "kpi_label": f"% of postings mentioning '{target_skill}'",
        "kpi_value": round(len(matching) / n, 3) if n else 0.0,
        "n_postings_analyzed": n,
        "n_matching": len(matching),
        "top_skills": [{"skill": s, "count": c} for s, c in all_skills.most_common(10)],
        "avg_skills_per_posting": round(sum(len(p.get("required_skills", [])) for p in postings) / n, 2) if n else 0.0,
    }

def main():
    postings = load_extracted()
    kpi = compute_kpi(postings)
    print(json.dumps(kpi, indent=2))
    with open("docs/data/kpi.json", "w") as f:
        json.dump(kpi, f, indent=2)
    print("\nWrote docs/data/kpi.json")

if __name__ == "__main__":
    main()
```
